2026-11-22 · 지난 미팅 이후

Phi 기반 RAG · Expert-CFG 재현, 이번 주 결과

Phi-3.5V에서 논문 수식 정의로 통일한 RAG와 Expert-CFG를 VQA-RAD와 SLAKE에 처음으로 끝까지 실행했습니다. 이번 주 결과, 논문과의 격차에 대한 분석, 그리고 팀이 함께 쓰는 환경 · 저장소 · 공유 폴더 정리를 담았습니다. Phi-3 쪽은 팀원 담당이며 이번 주 우리 쪽 실행 결과는 없습니다.

요약한 일설정결과분석논문 대조환경 점검공용 정리한계다음 주

요약

  1. 구현을 논문 수식에 맞춰 통일했습니다. 엔트로피(식 4), 하이라이트 임베딩 ×α(식 7), attention 가중 +log β / −δ(식 9·10)를 팀원 구현과 같은 정의로 맞췄고, 두 데이터셋에서 한 번씩 실행했습니다.
  2. 논문 방식(전문가 주석 = 정답) Expert-RAG는 논문 수준입니다. 베이스라인 대비 VQA-RAD +1.39 (논문 +1.33), SLAKE +1.01 (논문 +0.85). 정답이 입력에 들어가므로 규칙 완화로 표기하는 상한선입니다.
  3. 격차는 CFG 단계에서 납니다. Expert-RAG에서 Expert-CFG로 가는 증분이 VQA-RAD +0.46 (논문 +1.33), SLAKE +0.31 (논문 +1.70)로 논문의 약 1/3~1/5입니다. 원인은 아직 확정하지 못했습니다.
  4. 정답을 쓰지 않는 규칙 준수 Expert-CFG는 개선이 확인되지 않았습니다. VQA-RAD +0.44, SLAKE +0.77 (95% 구간 [−0.20, +1.74])로 논문의 +2.66 / +2.55에 못 미치고 구간이 0을 포함합니다.
  5. 공용 환경을 transformers 4.44.2로 고정했고 Phi-3.5V를 두 데이터셋 전 문항으로 점검했습니다. KV 캐시와 CFG 훅은 통과했고, 저장된 베이스라인 예측은 98.4% / 99.3% 일치합니다. 공용 레포(AIMS_basement)와 공유 폴더(AIMS_shared)를 만들었습니다.

행의 구분: 정답 사용 여부

규칙 준수 정답을 입력에 쓰지 않는 행. 하이라이트는 open은 검색 파일의 규칙, closed는 질문과 가장 많이 겹치는 캡션 문장입니다.

규칙 완화 논문 방식(전문가 주석 = 정답) 행. 5%로 선택된 문항 중 open은 캡션에 정답이 없으면 뒤에 정답.을 덧붙이고 정답 문자열을 하이라이트합니다(closed는 정답을 넣지 않음). 논문 5.2절이 open에 정답을 전문가 어노테이션으로 쓴다고 설명하는 것을 따랐고, test 정답이 입력에 들어가므로 규칙 준수 결과로 보고하지 않고 "전문가 주석이 있을 때의 상한선"으로 읽습니다.

공용 레포와 폴더 정리

팀이 같은 코드, 같은 체크포인트, 같은 입력으로 실험하도록 코드와 파일을 둘로 나눴습니다. 코드와 작은 파일은 레포(AIMS_basement, 비공개), 체크포인트와 큰 파일은 공유 Drive(AIMS_shared)에 두고, 레포는 파일의 위치와 sha256만 기록합니다.

레포 구조 (AIMS_basement)

common/        모델과 무관한 코드: 채점(vqa_scoring.py), 검색 파일 생성, 게이팅(gating.py), 하이라이트 규칙(highlights.py)
phi3/          Phi-3 전용 (환경, 팀원 코드 점검 노트북)
phi35/         Phi-3.5V 전용 (환경, transformers 4.44.2 점검 노트북)
data_common/   팀 공통 VQA-RAD 분할 (train 2,749 / val 315 / test 451, 이미지 단위)
manifests/     체크포인트와 큰 파일의 위치와 sha256
docs/          규칙(RULES.md), 불확실성 계산 명세(UNCERTAINTY_SPEC.md)
tests/         CPU 테스트 7개 (엔트로피 집계, 상위 5% 선택, AUC, 하이라이트, train QA 합치기, 검색 방식)
tools/         저자 파일 받기, 릴리스 해시 기록과 검증

Phi-3와 Phi-3.5V는 CFG 훅이 모델 내부 구조에 의존해서 폴더를 나눴고, 모델과 무관한 로직만 common/에 둡니다. 레포 규칙: 결과마다 규칙 구분과 채점 방식 표기, 비밀값 · 개인 정보 · 체크포인트 · 이미지 커밋 금지.

역할 분담과 인수인계

  • 팀원: Phi-3 쪽 RAG · CFG 실행과 불확실성(엔트로피, 식 4) 계산. Phi-3.5V를 먼저 하기로 했고, 같은 결과가 나오도록 모델 설정 · 문항 짝짓기 · 계산 · 출력 형식 · 점검 목록을 docs/UNCERTAINTY_SPEC.md에 적었습니다. num_crops=16이 빠지면 같은 답에 다른 이미지 토큰으로 엔트로피를 계산하게 되므로 명세에 명시했습니다.
  • 본인: Phi-3.5V의 RAG 세팅과 CFG 검증.
  • handoff 브랜치: 팀원이 쓰는 Expert-CFG 레포의 브랜치를 통일 정의와 공식 채점 표기로 갱신(원본 JSON 불필요, 실행 순서, 정답 주입 형식 포함).

한계와 미확인

  • 모든 결과가 1회 실행입니다. 시드 간 변동은 측정하지 않았습니다.
  • 5% 게이팅은 VQA-RAD 23문항, SLAKE 53문항만 바꿔서 구간이 넓고, 규칙 준수 Expert 행은 구간이 0을 포함합니다.
  • SLAKE 실행의 게이팅 정의가 기록되어 있지 않고, VQA-RAD의 신뢰구간과 w/ RAG 진단 출력은 받지 못했습니다.
  • 정답 주입 행에서 closed의 하이라이트 규칙이 규칙 준수 행과 다릅니다(검색 파일의 n-gram 대 겹치는 문장). 공용 모듈은 문장 규칙이라 구현이 어긋나 있고, 점수에 미친 영향은 확인하지 않았습니다.
  • 정답을 덧붙이는 형식이 논문의 "전문가가 참조를 수정한다"와 같은지는 확인하지 못했습니다. 정답이 이미 캡션에 있으면 하이라이트가 캡션 속 다른 문장의 같은 단어에 걸릴 수 있습니다(미검증).
  • KB가 논문과 다릅니다(ROCO 4,884건 부족, PathVQA 없음, GPT-4 문장화 없음). 캡션 없이 학습한 어댑터에 캡션을 붙이는 형식 불일치의 영향도 통제 실험을 하지 않았습니다.
  • 논문 Table 1의 수치는 HTML 추출값이라 원문과 한 번 더 대조해야 합니다.

다음 주 계획과 논의할 점

계획

  1. CFG가 정답 주입 Expert-RAG 대비 답을 바꾼 문항 수, 맞게 · 틀리게 바뀐 수, 하이라이트 토큰 분포 확인 (CFG 단계가 약한 이유를 직접 가르는 실험).
  2. VQA-RAD w/ RAG 진단, SLAKE 게이팅 정의 확인.
  3. 통제 실험: 섞은 캡션(프롬프트 형식 불일치 대 캡션 내용), 무작위 하이라이트, 검색 변형 비교(이미지→텍스트만 / PEIR+ROCO만).
  4. 팀원의 Phi-3.5V 엔트로피 파일을 받아 게이팅에 연결하고 우리 값과 대조.
  5. RAG · CFG 점수를 4.44.2에서 재현할 수 있도록 02 노트북 이식 검토.

의견을 구하고 싶은 것

  • 논문 방식(전문가 주석 = 정답) 행을 기본 비교 행으로 두고 규칙 완화로 표기하는 방식이 적절한지.
  • 규칙 준수 행에서 논문 수준에 가까워지려면 GPT-4 키워드 추출(부록 C) 같은 자동 주석을 도입할지, 현재의 규칙 기반 하이라이트를 유지할지.
  • Phi-3 결과가 나오면 Phi-3.5V와 같은 표(공식 채점, 규칙 구분)에 합치는 방식.
