# Expert-CFG 대조 점검: 논문 · 저자 코드 · 우리 구현, 그리고 RAG · CFG 개선 방법

작성 2026-11-26. 근거: arXiv:2507.09209v1 HTML 전문, 저자 레포 `ecoxial2007/Expert-CFG@edcb03c`(파일 36개), `transformers v4.43.0` 소스, 이 레포의 `RAG_CFG_results.md`. **GPU 실행은 하지 않았다.** 표시: [원문] [코드] 직접 읽음 · [추론] 읽은 것에서 끌어낸 판단 · [미확인].

## 0. 결론

1. **논문의 Expert 행은 정답 주입에 기대는 것으로 보인다.** 5.2절은 open 문항에서 정답을 전문가 주석으로 썼다고 밝히고[원문], Table 7의 "w/ 100% Expert-CFG"는 VQA-RAD 98.44, SLAKE 99.62, PathVQA 94.76이다(베이스라인 82.04 / 85.20 / 65.24)[원문]. 정답 없이는 설명하기 어려운 값이다[추론]. 교수님 기준으로는 논문의 Expert 수치를 목표로 삼을 수 없다.
2. **저자가 공개한 코드는 논문 수식과 다르다.** `demo.py`에는 식 7(임베딩 ×α)도 식 9(+log β)도 없고, 4.43.0의 마스크 처리에서는 하이라이트 가중치가 효과 없이 무조건부 가지 전체가 가려지는 것으로 읽힌다(2절).
3. **검색 · 엔트로피 · 주석 생성 · 학습 · 채점 코드는 공개되지 않았다**[코드].
4. 규칙 준수 개선의 병목은 CFG 수식보다 **검색된 참조에 답의 근거가 있는가**로 보인다[추론].

## 2. 저자 `demo.py`의 CFG가 실제로 하는 일

- [코드] 배치 0은 원래 mask(전부 1), 배치 1은 하이라이트 0.01 / 나머지 3.0인 mask다.
- [코드] 4.43.0 `_expand_mask`: `inverted = 1 - mask` 후 **0이 아닌 모든 위치**를 dtype 최솟값으로 채운다. 3.0 → −2, 0.01 → 0.99로 둘 다 0이 아니다. Phi-3.5V 원격 코드는 eager에서 이 함수를 쓴다(`_prepare_4d_causal_attention_mask`).
- [추론] 따라서 배치 1은 프롬프트 전체가 같은 값으로 가려져 맥락을 거의 보지 못하는 분포가 되고, 하이라이트 위치와 0.01 / 3.0 값은 결과에 영향이 없다. 실질은 식 5~6의 "맥락 없는 분포와 대비"에 가깝다. 우리 02도 5.x에서 같은 현상을 진단했다. **4.43 / 4.44 실행으로는 확인하지 않았다.** flash attention에서는 mask가 또 다르게 처리된다.
- 논문 Table 1이 이 코드로 나온 것인지는 [미확인].

## 5. 개선 방법 (규칙 준수만)

모든 선택은 **val에서** 하고 test는 확정한 설정으로 한 번만 본다. VQA-RAD val 315문항의 5%는 16문항이라 비교가 안 되므로, **설정은 val의 넓은 비율(전 문항 또는 상위 20%)에서 고르고** 보고만 5%로 한다. KB에는 train만 넣는다.

### 5.0 먼저 측정 (없으면 무엇이 막는지 모른다)
val과 선택 문항에 대해: 참조에 답 근거가 있는 비율(분석 전용, 입력에는 쓰지 않음), 하이라이트 토큰 수와 0개 비율, RAG → CFG에서 답이 바뀐 수(맞게 / 틀리게), 같은 이미지 train QA 비율. 대조군으로 **섞은 캡션**과 **무작위 하이라이트**.

### 5.1 검색 · KB (기대 효과 가장 큼)
- 지금은 train QA가 점수 척도 때문에 항상 이겨 **PEIR · ROCO가 전혀 안 쓰인다**(top-1 trainqa 100% / 99.9%). 출처별 점수 정규화, 출처별 1개씩, 또는 top-K 합치기(부록 F)를 비교한다.
- 후보 top-K를 질문 텍스트 유사도로 재정렬한다.
- train QA를 평서문으로 바꾼다(부록 B). 로컬 LLM으로 가능하다.
- `no` 제외는 closed를 yes 쪽으로 기울일 수 있다. 포함 / 제외를 비교한다.
- SLAKE open에서 정답이 캡션에 없으면 w/ RAG가 −11.27, 있으면 +4.41이었다(test 분석, 설정 선택에는 쓰지 말 것). 참조가 근거로 부족할 때 해를 끼친다는 신호다. 검색 점수가 낮으면 참조를 넣지 않는 규칙을 val에서 정해 볼 수 있다.
- VQA-RAD의 같은 이미지 train QA 사용은 교수님 확인이 필요하다.

### 5.2 하이라이트
- 문장 전체 대신 **의료 용어 단위**(논문의 2단계 추출 → 질문 매칭)를 시험한다.
- 마스크를 참조 구간에만 걸고 질문 구간은 제외한다.
- 첫 등장만 · 대소문자 구분인 매칭 때문에 놓치는 수를 세고, 전부 · 대소문자 무시(`phi3cfg.highlight_mask` 방식)와 비교한다.
- 토큰 수가 너무 많거나(PEIR 키워드 평균 46) 0개인 경우를 나눠 본다.

### 5.3 CFG
- 두 정의를 비교한다: (a) 식 7~10, (b) 저자 코드가 실질적으로 하는 **맥락 제거 대비**(2절). (b)는 명시적인 4D mask로 구현하고 "저자 코드 해석"이라고 표기한다.
- γ ∈ {1.3, 1.5, 2.0}, α, β, δ를 val에서 고른다. 규칙 준수 행이 γ 1.3과 1.5에서 같았으므로 **답이 바뀌는 문항 수부터** 센다.

### 5.4 게이팅 · 불확실성
- VQA-RAD에서 저장 엔트로피(`<|end|>` 포함)는 선택 오답 21/23, 식 4는 16/23이었다. 이것은 test 관찰이므로 **그대로 바꾸면 규칙 완화다.** 두 정의를 val에서 비교하고, 팀 공통 명세(`docs/UNCERTAINTY_SPEC.md`)를 바꾸려면 팀원과 합의한다.
- closed AUC 격차: yes/no 두 토큰만의 이진 엔트로피를 val에서 비교해 볼 수 있다(가설).
- 5% 비율은 논문과 비교하기 위해 고정한다.

### 5.5 프롬프트
- 어댑터는 캡션 없이 학습됐다. 참조임을 알리는 짧은 지시문, 참조 위치(이미지 앞 / 뒤)를 val에서 비교한다.
- 참조를 넣은 학습은 베이스라인을 바꾸므로 별도 연구다.

## 6. 권장 순서

1. 승인된 모듈화를 먼저 끝낸다 (설정 비교를 하려면 필요하다).
2. 5.0 진단을 `evaluate`에 추가한다.
3. 검색 변형 → 하이라이트 → CFG 정의 · γ → 게이팅 순으로 val에서 한 번에 하나씩.
4. 확정한 설정으로 test 한 번.

스펙의 "γ=1.5 고정"은 val 선택을 도입하면 "val에서 선택"으로 바꿀 수 있다. 바꾸기 전에 확인한다.
