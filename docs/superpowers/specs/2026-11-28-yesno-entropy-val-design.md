# 설계: yes/no 불확실성 정의를 val에서 비교

작성 2026-11-28. 크기: 작은 변경. 상태: 승인(2026-11-28, D1 · D2는 확인용으로 범위 축소).

## 목적
논문 Table 6의 파인튜닝 closed AUC(VQA-RAD 0.958, SLAKE 0.949)와 우리 값(test 약 0.80)의 차이가 **엔트로피를 계산하는 확률의 정의**에서 오는지 확인한다. 0.958 도달은 목표이지 보장이 아니다.

- 하는 것: val의 yes/no 문항에서 정의별 AUC 비교.
- **공식 정의는 D0(명세의 식 4)로 유지한다.** D1 · D2는 원인 확인용이다.
- 하지 않는 것: 학습, 베이스라인 변경, RAG · CFG 변경, 정의 채택, test 계산.

## 방법 비교
| 방법 | 비용 | 선택 |
|---|---|---|
| A. yes/no 확률을 따로 계산해 val에서 비교 | GPU 몇 분(+ val 생성) | **선택** |
| B. 학습 조건을 바꿔 다시 학습 | 큼, 베이스라인이 바뀜 | 근거가 없어 제외 |
| C. 저자에게 계산 방법 문의 | 작음 | 보류 (이번 범위 밖) |

## 대상
- VQA-RAD val 315문항 중 정답이 yes/no인 184문항. SLAKE val의 yes/no 문항.
- 모델: 릴리스 어댑터(`phi35-vqarad-e10-s42-v1`, `phi35-slake-e5-s42-v1`), 4.44.2, bf16, eager.
- 예측: `phi35cfg.infer --mode baseline --split val`로 새로 만든다(기존 기능).
- 오답: `score_phi` 점수 < 1.

## 계산
문항마다 forward 1번, 답의 **첫 토큰 위치** 분포에서 다음을 저장한다. 원시 확률을 저장하므로 아래 정의는 모두 CPU에서 계산한다.
- 토크나이저 어휘 중 `strip().lower()`가 `yes` / `no`인 토큰 id 전부와 각 확률
- 전체 어휘 엔트로피

| 이름 | 정의 |
|---|---|
| D0 | 명세의 식 4 (현재 기준, 비교 대상) |
| D1 | 대소문자 · 띄어쓰기 변형을 yes, no 두 칸으로 합친 뒤의 전체 어휘 엔트로피 |
| D2 | yes, no만 남겨 다시 정규화한 이진 엔트로피 |

## 보고
- 지표: 데이터셋별 AUC, D1 · D2와 D0의 차이는 문항 쌍 부트스트랩 95% 구간.
- 채택 판정은 없다. 결과가 좋아도 명세(`docs/UNCERTAINTY_SPEC.md`)와 게이팅은 바꾸지 않는다.
- D1 · D2 수치는 논문의 식 4가 아니라 우리가 바꾼 정의임을 함께 적는다.

## 한계
- VQA-RAD val은 closed 오답이 수십 개 수준일 것으로 보여 구간이 넓다. 작은 차이는 판별하지 못한다.
- val은 체크포인트 선택에도 썼다. 정의 간 비교에는 쓸 수 있지만 AUC의 절댓값은 낙관적일 수 있다.
- SLAKE 예측은 test에서 `Yes` / `No`만 나왔으므로 D1의 효과가 작을 수 있다.

## 만들 것
- `phi35cfg`에 yes/no 확률을 저장하는 모드(val 전용), CPU 비교 보고, CPU 테스트.
- `Phi35V_run.ipynb`에 실행 셀.
- 세부 파일 구성은 구현자가 정한다. 비교 결과 파일은 Drive에 두고 레포에는 올리지 않는다.
